# Этап 3: виртуальная файловая система

## Формат образа

Образ — текстовый CSV в UTF-8 с обязательным заголовком `path,type,content`.
Разделитель — запятая. Кавычки и удвоенные кавычки обрабатываются стандартным CSV-парсером .NET
`Microsoft.VisualBasic.FileIO.TextFieldParser`; внешние пакеты не требуются.
Пустые строки пропускаются. Значения полей не обрезаются по краям.

```csv
path,type,content
/motd,file,SGVsbG8hCg==
/home,directory,
/home/user,directory,
/home/user/note.txt,file,SGVsbG8=
"/comma,name.bin",file,AAEC/w==
```

| Поле | Правила |
| --- | --- |
| `path` | Абсолютный виртуальный UNIX-путь, например `/home/user/note.txt` |
| `type` | `directory` для каталога, `file` для файла; регистр значим |
| `content` | Пустое поле каталога; Base64 содержимого любого файла, в том числе текстового |

Текст перед кодированием в Base64 переводится в байты UTF-8. Двоичные файлы хранят произвольные байты.
Пустое поле `content` у файла означает файл длиной ноль байтов.

Вложенность задаётся полными путями. Каждый родительский каталог, кроме корня, должен быть указан явно.
Порядок строк произвольный: файл может предшествовать своему каталогу.
Корень `/` создаётся автоматически, если не указан; явная запись корня должна иметь тип `directory`.
Заголовок без записей — корректный минимальный образ.

Пути регистрозависимы: `/A` и `/a` различаются даже при запуске на Windows.
Пробелы, кириллица и запятые в именах допускаются. Запятые заключаются в CSV-кавычки,
а кавычка внутри поля удваивается: `"/say""hello"` означает путь `/say"hello`.
Относительные пути, пустые сегменты, завершающий `/` вне корня, `.` и `..`, обратная косая черта
и управляющие символы запрещены. Виртуальные пути никогда не передаются файловым API реальной ОС.

## Запуск и motd

```powershell
.\run.bat --vfs "examples\vfs\deep.csv" --script "examples\stage3-success.txt"
```

Порядок запуска: проверка параметров → вывод настроек → загрузка и проверка VFS → вывод `/motd` → скрипт → REPL.
Без `--vfs` создаётся пустая VFS с корнем. Указанный файл должен существовать и быть доступен для чтения.

Сообщение берётся только из файла `/motd` в корне. Вложенные `motd` и каталог `/motd` игнорируются.
Текст декодируется как UTF-8; если в конце нет перевода строки, он добавляется перед следующим выводом.
Пустой файл ничего не выводит. Некорректный UTF-8 в `/motd` вызывает ошибку загрузки.

Повреждённый CSV, неизвестный тип, неверный Base64, повторный путь, отсутствующий родитель
и попытка использовать файл как родительский каталог отклоняются. Ошибка завершает приложение с кодом `1`
до исполнения команд. Для ошибок содержимого записи выводится номер строки CSV.

## Архитектура

| Компонент | Ответственность |
| --- | --- |
| `VirtualPath` | Проверка виртуальных путей и получение родительского пути |
| `VfsEntry` | Путь, тип записи и байты содержимого; защитное копирование массивов |
| `VirtualFileSystem` | Индекс записей в памяти и проверка целостности дерева |
| `CsvVfsLoader` | Чтение источника, CSV-парсинг, декодирование Base64 и создание модели |
| `VfsStartup` | Выбор пустой/загруженной VFS и вывод приветствия |
| `Application` | Порядок запуска и обработка ошибок |
| `Shell` | Хранение готовой VFS сессии, REPL, скрипты и реестр команд |

Формат CSV и физический путь источника не передаются в оболочку или команды.
После `CsvVfsLoader.Load` источник закрыт: чтение содержимого записей выполняется только из памяти.
Образ не распаковывается, файлы на диске не создаются, исходный CSV не изменяется.
Модель не содержит операций записи на диск. Защитные копии исключают изменение файлов через возвращённый массив.

На этапе 3 `ls` и `cd` остаются заглушками. Подключённая VFS доступна через `Shell.GetFileSystem()`;
в этапе 4 её можно передать обработчикам команд через обычные конструкторы.
Диспетчер команд по-прежнему использует `ICommand` и словарь, без растущего `switch`.
Полная реализация `ls`, `cd`, `find` и `rev` относится к этапу 4, `cp` и `help` — к этапу 5.

### Методы

- `VirtualPath.Validate` проверяет путь; `GetParent` возвращает его родительский каталог.
- Конструктор `VfsEntry` проверяет запись и копирует байты; `GetPath` и `IsDirectory` возвращают метаданные.
  `ReadContent` возвращает копию содержимого файла и запрещает чтение каталога.
- Конструкторы `VirtualFileSystem` создают пустую VFS или индекс из записей; `ValidateTree` проверяет связи.
  `Contains` проверяет наличие пути, `GetEntry` возвращает запись либо сообщает об отсутствии.
- `CsvVfsLoader.Load` открывает и закрывает файл, `Read` разбирает текстовый поток.
  `Read` также закрывает переданный поток при освобождении CSV-парсера.
  `ValidateHeader` проверяет заголовок, `ReadEntries` собирает записи, `ParseEntry` проверяет поля и Base64.
- `VfsStartup.Load` выбирает источник, `PrintMessage` выводит `/motd`.
- `Application.Start` связывает компоненты; `Shell.GetFileSystem` возвращает VFS текущей сессии.

## Демонстрации

```powershell
.\scripts\check-vfs-images.bat
.\scripts\check-vfs-errors.bat
```

Первый скрипт запускает эмулятор последовательно с тремя образами:

- `minimal.csv`: только корень, нет приветствия.
- `several files.csv`: приветствие на русском, текстовый и двоичный файлы, имя с запятой и пустой каталог.
- `deep.csv`: дерево `/home/student/projects/demo/source.txt`, несколько файлов на разных уровнях.

Для каждого образа выполняется `examples/stage3-success.txt`: пустая строка, `ls` без аргументов,
несколько аргументов, кавычки, переменные окружения, `cd` без аргументов и с путём, `exit`.
Пути в выводе заглушек пока не проверяются на существование в образе.

Второй скрипт проверяет повреждённый Base64, отсутствующий каталог-родитель и отсутствующий CSV,
а затем ошибки неизвестной команды, аргументов `cd`, аргументов `exit` и незакрытой кавычки.
Для каждой ошибки команд используется отдельный стартовый скрипт: по условиям выполнение прекращается
на первой ошибке. Строка `ls NEVER` после неё не должна появляться в выводе.

Сценарии этапа 2 `check-options.bat` и `check-errors.bat` обновлены для работы с реальным CSV-образом.
Проверки `VfsTests` охватывают модель, повреждённые образы, вложенность и независимость от источника;
`VfsStartupTests` проверяют приветствие, порядок запуска, неизменность CSV и остановку до запуска команд.
