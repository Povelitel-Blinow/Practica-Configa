# Эмулятор оболочки: вариант №9

Практическая работа №1 по конфигурационному управлению, группа ИКБО-20-25.
Эмулятор написан на C# и запускается в консоли. Сейчас реализованы этапы 1–4:
ввод команд, параметры запуска, виртуальная файловая система (VFS) и команды `ls`, `cd`, `find`, `rev`.

Требования взяты из «ИКБО-20-25-1.pdf»: оформление описано на страницах 4–7,
вариант №9 — на страницах 32–34. Для этапа 5 остаётся реализовать `cp` и `help`.

Проект использует .NET 10, но версия языка ограничена C# 5 через `LangVersion` в файлах проектов.

## Возможности

Консольный прототип читает команды, разбирает аргументы, выполняет команду и снова показывает приглашение.
Приглашение `username@hostname:~$ ` использует реальные `Environment.UserName` и `Environment.MachineName`.
Символ `~` пока обозначает условный домашний каталог эмулятора.

| Команда | Аргументы | Поведение |
| --- | --- | --- |
| `ls` | Ноль или несколько путей | Выводит имя файла или непосредственное содержимое каталога |
| `cd` | Ноль или один путь | Меняет текущий каталог VFS; без пути переходит в `/` |
| `find` | `[путь] [-name маска]` | Обходит дерево от заданного пути; без пути — от текущего каталога |
| `rev` | Ноль или несколько файлов | Переворачивает каждую строку UTF-8-текста; без файлов читает ввод до EOF |
| `exit` | Без аргументов | Завершает оболочку |

Рабочий каталог при запуске — `/`. Все файловые команды работают с VFS в памяти.
`cd` не меняет каталог процесса ОС. Поддерживаются абсолютные и относительные пути,
`.` и `..`; переход выше корня оставляет каталог `/`. Пути регистрозависимы.
Пропущенный путь и явно переданный пустой аргумент различаются: пустой путь вызывает ошибку.
Приглашение сохраняет вид `username@hostname:~$`; текущий каталог в нём пока не отображается.

`ls` выводит имена по одному на строку в порядке `StringComparer.Ordinal`, включая скрытые файлы.
Для нескольких путей перед каждым результатом печатается заголовок. UNIX-флаги `ls` не реализованы.
`find` выводит абсолютные пути, включая начальную запись; обходит каталоги в отсортированном порядке.
В `-name` поддерживаются `*` (любое число символов) и `?` (один символ), регистр значим.
Без совпадений команда завершается успешно и ничего не выводит.

`rev` обрабатывает файлы по порядку, сохраняет пустые строки и переворачивает текстовые элементы Unicode.
Каталоги и файлы с некорректным UTF-8 вызывают ошибку. Для каждой прочитанной строки выводится перевод строки,
в том числе если последняя строка исходного файла им не заканчивалась. Пустой файл ничего не выводит.
Без аргументов `rev` читает стандартный ввод оболочки до EOF; строки стартового скрипта остаются командами.
В Windows EOF вводится через Ctrl+Z и Enter, в Unix-подобных ОС — Ctrl+D.

Ошибки выводятся в stderr. После ошибки интерактивный диалог продолжается,
а стартовый скрипт останавливается с кодом `1`. В командах с несколькими путями
вывод уже обработанных файлов сохраняется, выполнение прекращается на первом ошибочном пути.
Пустая строка игнорируется; EOF завершает интерактивный режим.

### Правила разбора

- Пробельные символы, в том числе пробелы и табуляции, разделяют аргументы; повторные разделители игнорируются.
- Одинарные и двойные кавычки позволяют передать аргумент с пробелами, включая пустую строку.
- `$NAME` и `${NAME}` раскрываются из окружения реальной ОС, в том числе внутри двойных кавычек.
- В одинарных кавычках подстановка отключена. Соседние фрагменты `ab" cd"` образуют один аргумент.
- Имена переменных имеют вид `[A-Za-z_][A-Za-z0-9_]*`; отсутствующая переменная даёт пустую строку.
- Значения переменных не разбиваются на слова и повторно не раскрываются.
- В этом прототипе нет экранирования, конвейеров, перенаправлений, подстановки команд и раскрытия `~`.

Переменные зависят от ОС: в Windows доступны `$USERPROFILE` и `$TEMP`, в Linux обычно `$HOME`.
Если `$HOME` не задана в Windows, результатом её подстановки будет пустая строка.

## Сборка и запуск

Требуется установленный **.NET SDK 10.0** или совместимый SDK с поддержкой `net10.0`.
Сторонних пакетов нет; `NuGet.Config` отключает внешние источники пакетов.
Все команды выполняются из корня репозитория:

```text
dotnet build ShellEmulator.sln
dotnet run --project src/ShellEmulator
```

В Windows также можно запустить `run.bat` из любого каталога.
Скрипт `run.bat` передаёт параметры приложению.

## Этап 2: параметры и стартовый скрипт

| Параметр | Значение | По умолчанию |
| --- | --- | --- |
| `--vfs` | Путь к физическому файлу VFS | Пустая строка |
| `--script` | Путь к стартовому скрипту UTF-8 | Пустая строка, сразу REPL |

Параметры необязательны и задаются парами в любом порядке. Пути с пробелами заключаются в кавычки.
Неизвестный параметр, повтор параметра или отсутствие непустого значения дают ошибку и код завершения `1`.
Значение, начинающееся с `--`, считается пропущенным путём; для такого имени файла укажите префикс `./`.
При корректных параметрах приложение сначала выводит обе настройки: `VFS: ...` и `Script: ...`.
Начиная с этапа 3 указанный CSV-образ VFS загружается и проверяется; без параметра создаётся пустая VFS.
Относительный путь скрипта считается от рабочего каталога процесса; `run.bat` устанавливает корень проекта.

```powershell
.\run.bat --vfs "examples\vfs\several files.csv" --script "examples\startup success.txt"
dotnet run --project src/ShellEmulator -- --vfs "examples/vfs/deep.csv" --script "examples/stage3-success.txt"
```

Скрипт содержит по одной команде на строку и использует тот же парсер, что REPL.
Перед выполнением каждой строки выводится приглашение вместе с командой, затем её результат.
Первая ошибка разбора или выполнения прекращает скрипт и приложение с кодом `1`.
При недоступном файле выводится ошибка чтения/доступа. Команда `exit` завершает приложение с кодом `0`.
После успешного конца файла начинается интерактивный режим; пустой файл также допускается.
Комментарии в стартовых скриптах пока не поддерживаются.

Демонстрационные скрипты реальной ОС Windows:

```powershell
.\scripts\check-options.bat
.\scripts\check-errors.bat
```

Первый проверяет запуск без параметров, каждый параметр отдельно, оба порядка и пути с пробелами.
Второй демонстрирует ошибочные параметры, отсутствующий файл и остановку на первой ошибке скрипта.
Каждый скрипт возвращает `0` при ожидаемых результатах, `1` — при несоответствии.
В `examples/startup-error.txt` строка `ls NEVER` не должна появиться в выводе: до неё выполнение не дойдёт.

## Этап 3: VFS

VFS загружается из CSV в память; содержимое файлов хранится в Base64. Исходный образ не изменяется.
При старте перед командами выводится UTF-8-текст корневого файла `/motd`, если он есть.
Загрузчик CSV, модель файловой системы и логика запуска разделены; оболочка принимает уже загруженную модель.

Формат CSV, ограничения путей, описание методов и примеры: [docs/VFS.md](docs/VFS.md).

```powershell
.\scripts\check-vfs-images.bat
.\scripts\check-vfs-errors.bat
```

В репозитории есть минимальный образ, образ с несколькими файлами и дерево глубиной более трёх уровней.
Скрипты демонстрируют загрузку, приветствие, команды предыдущих этапов и обработку ошибок.

## Тесты

```text
dotnet run --project tests/ShellEmulator.Tests
```

В Windows эквивалентная команда — `test.bat`.
Тесты оформлены как консольная программа и запускаются через `dotnet run`.
При успехе выводится `PASS: N checks`, где `N` — число пройденных проверок, и возвращается код `0`.
При ошибке выводится `FAIL: ...` и возвращается код `1`.
Проверяются разбор аргументов, кавычки, переменные, ошибки, файловые команды, приглашение, завершение по `exit` и EOF.
Тесты временно меняют только собственную переменную окружения процесса и восстанавливают её после выполнения.
Проверки этапа 2 охватывают настройки, вывод параметров, ошибки скрипта, переход в REPL
и добавление команды в реестр. Проверки VFS охватывают CSV, Base64, связи файлов и каталогов,
вывод `/motd` и независимость загруженных данных от исходного CSV.
Временные файлы скриптов и образов удаляются после проверки.

## Этап 4: примеры файловых команд

```powershell
.\run.bat --vfs "examples\vfs\stage4.csv" --script "examples\stage4-success.txt"
.\scripts\check-stage4.bat
```

`stage4-success.txt` показывает списки каталогов, несколько путей, переходы по дереву,
поиск с масками и без них, чтение нескольких файлов, Unicode и пустой файл.
Скрипт `check-stage4.bat` дополнительно проверяет режим `rev` со стандартным вводом
и отдельные сценарии ошибок. Каждый ошибочный сценарий содержит `ls NEVER` после ошибки:
эта строка не должна выполняться. Проверяются отсутствующие и пустые пути, лишние аргументы,
переход в файл, чтение каталога, неверный UTF-8 и некорректный проход через файл.

Для интерактивной проверки запустите:

```powershell
.\run.bat --vfs "examples\vfs\stage4.csv"
```

Приглашение ниже сокращено до `$`:

```text
$ cd /docs
$ ls
.hidden
hello.txt
space name.txt
sub
$ find . -name "hello*"
/docs/hello.txt
$ rev hello.txt
cba
тевирП
$ cd /missing
Ошибка: Путь отсутствует в VFS: /missing
$ ls hello.txt
hello.txt
$ cd ..
$ exit
```

Кавычки и переменные разбираются до выполнения команды. Переменная реальной ОС
не делает путь доступным в VFS: например, `$USERPROFILE` обычно указывает на каталог,
которого нет в виртуальном образе. Примеры разбора без обращения к такому пути:
`find / -name "$USERPROFILE"`, `find / -name '$HOME'`.

## Структура и функции

Исходники находятся в `src/ShellEmulator`, проверки — в `tests/ShellEmulator.Tests`,
образы VFS и стартовые скрипты — в `examples`, сценарии проверки для Windows — в `scripts`.

- `src/ShellEmulator/Program.cs` — настройка UTF-8 и возврат кода завершения приложения.
- `Application.Run` — параметры, отладочный вывод, стартовый скрипт, REPL и обработка ошибок запуска.
- `Application.Start` — загрузка VFS, приветствие и последовательный запуск скрипта и REPL.
- `Application.RunStartupScript` — открытие и гарантированное закрытие файла скрипта.
- `StartupOptions.Parse` — проверка параметров; `GetVfsPath` и `GetScriptPath` возвращают заданные пути.
  Конструктор `StartupOptions` задаёт пустые пути по умолчанию.
- `CommandParser.Parse` — разбор строки в массив команды и аргументов.
- `CommandParser.ExpandFragment` — снятие кавычек и раскрытие переменных.
- `CommandParser.ExpandVariables` — сборка строки с подстановками обычным циклом.
- `CommandParser.ExpandVariable` — получение значения переменной окружения.
- `CommandParser.AddWord` — сохранение собранного аргумента, включая пустой.
- `Shell.GetPrompt` — приглашение по данным ОС.
- Конструктор `Shell` — сохранение потоков и регистрация встроенных команд.
- `Shell.RegisterCommand` — добавление команды в словарь с запретом повторного имени.
- `Shell.GetFileSystem` — доступ к VFS текущей сессии; компонентам VFS посвящён `docs/VFS.md`.
- `Shell.Run` — цикл чтения и выполнения команд.
- `Shell.RunScript` — отображение строк скрипта и выполнение до ошибки, exit или конца файла.
- `Shell.Execute` — контракт REPL: продолжать после ошибки, завершить после exit.
- `Shell.ExecuteCommand` — разбор строки и возврат `Success`, `Error` или `Exit`.
- `Shell.Dispatch` — поиск обработчика в словаре и вызов общего метода `Execute` без switch.
- `Commands/ICommand` — интерфейс обработчика; `LsCommand`, `CdCommand`, `ExitCommand` — реализации.
  Каждый метод `Execute` проверяет аргументы своей команды и возвращает `CommandResult`.
  Для новой команды создайте класс с интерфейсом `ICommand` и вызовите `RegisterCommand`.
  Менять диспетчер, парсер или цикл чтения для этого не нужно.
- `CommandResult` — результат выполнения: `Success` продолжает работу, `Error` обозначает ошибку,
  `Exit` завершает оболочку.
- `tests/ShellEmulator.Tests` — автономные проверки; `Main` запускает группы проверок.
  `CheckParser`, `CheckCommands`, `CheckRepl` проверяют соответствующие части программы.
  `Equal`, `ExpectParseError`, `Require` сравнивают результаты и регистрируют ошибки.
- `StageTwoTests.Run` — проверки параметров, ошибок сценария, реестра и запуска приложения.
  Методы `CheckOptions`, `CheckInvalidOptions`, `CheckScriptErrors`, `CheckRegistry`, `CheckApplication`
  проверяют соответствующие сценарии; вспомогательные методы проверяют успешный запуск и остановку.
- `VfsTests.Run` — проверки образов и модели VFS. `CheckValidImages` проверяет корректные CSV,
  `CheckInvalidImages` и `CheckInvalidPaths` — ошибочные записи и пути,
  `CheckContentIsolation` — копирование содержимого, `CheckSourceIndependence` — работу без исходного файла.
  `Read` загружает CSV из строки, `ExpectInvalid` проверяет отказ загрузчика, `Require` проверяет условие.
- `VfsStartupTests.Run` — проверки VFS при запуске приложения.
  `CheckMessages` и `Message` проверяют вывод приветствия, `CheckStartupOrder` — порядок запуска,
  `CheckInvalidStartup`, `CheckRejectedStartup` и `CheckMissingFile` — остановку при ошибке VFS.
  `Require` проверяет условие.
- `run.bat`, `test.bat` — запуск приложения и тестов из корня репозитория.

### Функции этапа 4

- `VfsSession` хранит VFS и текущий каталог, начиная с `/`.
  `GetDirectory` возвращает каталог, `GetFileSystem` — модель, `Resolve` разрешает путь,
  `ChangeDirectory` меняет каталог после проверки, `RequireDirectory` проверяет тип записи.
- `VirtualFileSystem.GetChildren` возвращает отсортированные пути непосредственных потомков.
- Конструкторы `LsCommand`, `CdCommand` и `FindCommand` принимают общую сессию.
  Конструктор `RevCommand` также принимает стандартный ввод.
- `LsCommand.Execute` обрабатывает пути, `PrintEntry` печатает файл или детей каталога.
- `CdCommand.Execute` проверяет аргументы и меняет каталог.
- `FindCommand.Execute` проверяет аргументы и создаёт маску, `Walk` обходит дерево через стек.
- `RevCommand.Execute` читает UTF-8-файлы или ввод, `PrintLines` переворачивает строки по текстовым элементам.
- `StageFourTests.Run` запускает проверки этапа; `CreateFileSystem` создаёт тестовое дерево,
  `CheckNavigation`, `CheckFind`, `CheckRev`, `CheckErrors` проверяют команды и ошибки,
  `Require` считает проверки и сообщает о провале.

### Функции VFS

- `VirtualPath.Validate` проверяет абсолютный виртуальный путь; `GetParent` возвращает путь родителя.
- Конструктор `VfsEntry` проверяет запись и копирует её содержимое.
  `GetPath` возвращает путь, `IsDirectory` — признак каталога, `ReadContent` — копию байтов файла.
- Конструкторы `VirtualFileSystem` создают пустую систему или загружают набор записей.
  `ValidateTree` проверяет родительские каталоги, `Contains` проверяет наличие пути,
  `GetEntry` возвращает запись по пути.
- `CsvVfsLoader.Load` открывает CSV-файл, `Read` читает текстовый поток и создаёт VFS.
  `ValidateHeader` проверяет заголовок, `ReadEntries` собирает записи,
  `ParseEntry` проверяет поля и декодирует Base64.
- `VfsStartup.Load` загружает указанный образ или создаёт пустую VFS.
  `PrintMessage` выводит содержимое корневого файла `/motd` как UTF-8.

Подробные правила формата и примеры образов приведены в [docs/VFS.md](docs/VFS.md).
