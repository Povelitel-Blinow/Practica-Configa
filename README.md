# Эмулятор оболочки: вариант №9

Практическая работа №1, ИКБО-20-25. Реализованы **этапы 1–2 из 5: REPL и конфигурация** на C# (.NET 8).
Условия: «ИКБО-20-25 (1).pdf», правила на страницах 4–7, вариант №9 на страницах 32–34.

Код написан в классическом стиле: явные типы, обычные классы и конструкторы,
метод Main, циклы, условия, интерфейсы и словарь обработчиков. Нет LINQ, лямбда-выражений,
top-level statements, диапазонов, primary constructors и collection expressions.
В проектах установлен LangVersion=5: компилятор запрещает синтаксис новее C# 5.
Среда выполнения остаётся .NET 8; для корректного JSON-вывода используется стандартная библиотека.

## Возможности

Консольный прототип читает команды, разбирает аргументы, выполняет команду и снова показывает приглашение.
Приглашение `username@hostname:~$ ` использует реальные `Environment.UserName` и `Environment.MachineName`.
Символ `~` пока обозначает условный домашний каталог эмулятора.

| Команда | Аргументы | Поведение |
| --- | --- | --- |
| `ls` | Любое число аргументов | Выводит `ls` и аргументы в формате JSON |
| `cd` | Ноль или один путь | Выводит `cd` и аргументы в формате JSON |
| `exit` | Без аргументов | Завершает оболочку |

`ls` и `cd` — заглушки: не читают файлы и не меняют рабочий каталог ОС.
У `ls` пока нет проверки существования путей и семантики флагов: они просто выводятся.
Ошибки неизвестной команды, лишних аргументов `cd`/`exit` и незакрытых кавычек выводятся в stderr.
В интерактивном режиме после ошибки диалог продолжается; стартовый скрипт останавливается при первой ошибке.
Пустая строка игнорируется; конец интерактивного потока ввода завершает программу.

### Правила разбора

- Пробелы и табуляции разделяют аргументы; повторные разделители игнорируются.
- Одинарные и двойные кавычки позволяют передать аргумент с пробелами, включая пустую строку.
- `$NAME` и `${NAME}` раскрываются из окружения реальной ОС, в том числе внутри двойных кавычек.
- В одинарных кавычках подстановка отключена. Соседние фрагменты `ab" cd"` образуют один аргумент.
- Имена переменных имеют вид `[A-Za-z_][A-Za-z0-9_]*`; отсутствующая переменная даёт пустую строку.
- Значения переменных не разбиваются на слова и повторно не раскрываются.
- В этом прототипе нет экранирования, конвейеров, перенаправлений, подстановки команд и раскрытия `~`.

Переменные зависят от ОС: в Windows доступны `$USERPROFILE` и `$TEMP`, в Linux обычно `$HOME`.
Если `$HOME` не задана в Windows, результатом её подстановки будет пустая строка.

## Сборка и запуск

Требуется установленный **.NET SDK 8.0** или совместимый SDK с поддержкой `net8.0`.
Сторонних пакетов нет; `NuGet.Config` отключает внешние источники пакетов.
Все команды выполняются из корня репозитория:

```text
dotnet build ShellEmulator.sln
dotnet run --project src/ShellEmulator
```

В Windows также можно запустить `run.bat` из любого каталога.
Скрипт `run.bat` передаёт параметры приложению. VFS и полноценные файловые команды относятся к этапам 3–5.

## Этап 2: параметры и стартовый скрипт

| Параметр | Значение | По умолчанию |
| --- | --- | --- |
| `--vfs` | Путь к физическому файлу VFS | Пустая строка |
| `--script` | Путь к стартовому скрипту UTF-8 | Пустая строка, сразу REPL |

Параметры необязательны и задаются парами в любом порядке. Пути с пробелами заключаются в кавычки.
Неизвестный параметр, повтор параметра или отсутствие непустого значения дают ошибку и код завершения `1`.
Значение, начинающееся с `--`, считается пропущенным путём; для такого имени файла укажите префикс `./`.
При корректных параметрах приложение сначала выводит обе настройки: `VFS: ...` и `Script: ...`.
Путь VFS на этом этапе только сохраняется и выводится: файл не открывается и может ещё не существовать.
Относительный путь скрипта считается от рабочего каталога процесса; `run.bat` устанавливает корень проекта.

```powershell
.\run.bat --vfs "examples\virtual disk.csv" --script "examples\startup success.txt"
dotnet run --project src/ShellEmulator -- --vfs "disk.csv" --script "examples/startup success.txt"
```

Скрипт содержит по одной команде на строку и использует тот же парсер, что REPL.
Перед выполнением каждой строки выводится приглашение вместе с командой, затем её результат.
Первая ошибка разбора или выполнения прекращает скрипт и приложение с кодом `1`.
При недоступном файле выводится ошибка чтения/доступа. Команда `exit` завершает приложение с кодом `0`.
После успешного конца файла начинается интерактивный режим; пустой файл также допускается.
Комментарии в стартовых скриптах пока не поддерживаются.

Демонстрационные скрипты реальной ОС Windows:

```powershell
.\scripts\check-options.bat
.\scripts\check-errors.bat
```

Первый проверяет запуск без параметров, каждый параметр отдельно, оба порядка и пути с пробелами.
Второй демонстрирует ошибочные параметры, отсутствующий файл и остановку на первой ошибке скрипта.
Каждый скрипт возвращает `0` при ожидаемых результатах, `1` — при несоответствии.
В `examples/startup-error.txt` строка `ls NEVER` не должна появиться в выводе: до неё выполнение не дойдёт.

## Тесты

```text
dotnet run --project tests/ShellEmulator.Tests
```

В Windows эквивалентная команда — `test.bat`.
Это автономный консольный набор проверок, а не проект тестового фреймворка; запускайте его через `dotnet run`.
Успешный результат: `PASS: 76 checks`, код завершения `0`; ошибка даёт код `1`.
Проверяются разбор аргументов, кавычки, переменные, ошибки, заглушки, приглашение, завершение по `exit` и EOF.
Тесты временно меняют только собственную переменную окружения процесса и восстанавливают её после выполнения.
Проверки этапа 2 также создают временный файл скрипта и удаляют его после проверки.
Проверяются настройки, отладочный вывод, все типы ошибок скрипта, переход в REPL и расширение реестра команд.

## Интерактивная демонстрация

Запустите `run.bat` и вводите команды по одной. Имя пользователя, компьютер и пути будут вашими.
Приглашение в примере сокращено до `$`; программа выводит его полностью.
JSON может экранировать символы в путях (например, обратную косую черту).

```text
$ ls
ls: []
$ ls -l /tmp
ls: ["-l","/tmp"]
$ cd "my folder"
cd: ["my folder"]
$ cd
cd: []
$ ls "$USERPROFILE"
ls: ["C:\\Users\\vladi"]
$ cd ${TEMP}
cd: ["C:\\Users\\vladi\\AppData\\Local\\Temp"]
$ ls '$USERPROFILE'
ls: ["$USERPROFILE"]
$ cd one two
Ошибка: cd принимает не более одного аргумента. Использование: cd [путь]
$ unknown
Ошибка: неизвестная команда: unknown
$ ls "unclosed
Ошибка: Незакрытая кавычка.
$ exit 1
Ошибка: exit не принимает аргументы. Использование: exit
$ exit
```

Дополнительно нажмите Enter на пустой строке: появится следующее приглашение без ошибки.
Для проверки EOF в Windows нажмите Ctrl+Z и Enter; в Unix-подобной ОС — Ctrl+D на пустой строке.

## Структура и функции

- `src/ShellEmulator/Program.cs` — настройка UTF-8 и возврат кода завершения приложения.
- `Application.Run` — параметры, отладочный вывод, стартовый скрипт, REPL и обработка ошибок запуска.
- `Application.RunStartupScript` — открытие и гарантированное закрытие файла скрипта.
- `StartupOptions.Parse` — проверка параметров; `GetVfsPath` и `GetScriptPath` возвращают заданные пути.
- `CommandParser.Parse` — разбор строки в массив команды и аргументов.
- `CommandParser.ExpandFragment` — снятие кавычек и раскрытие переменных.
- `CommandParser.ExpandVariables` — сборка строки с подстановками обычным циклом.
- `CommandParser.ExpandVariable` — получение значения переменной окружения.
- `CommandParser.AddWord` — сохранение собранного аргумента, включая пустой.
- `Shell.GetPrompt` — приглашение по данным ОС.
- Конструктор `Shell` — сохранение потоков и регистрация встроенных команд.
- `Shell.RegisterCommand` — добавление команды в словарь с запретом повторного имени.
- `Shell.Run` — цикл чтения и выполнения команд.
- `Shell.RunScript` — отображение строк скрипта и выполнение до ошибки, exit или конца файла.
- `Shell.Execute` — контракт REPL: продолжать после ошибки, завершить после exit.
- `Shell.ExecuteCommand` — разбор строки и возврат `Success`, `Error` или `Exit`.
- `Shell.Dispatch` — поиск обработчика в словаре и вызов общего метода `Execute` без switch.
- `Commands/ICommand` — интерфейс обработчика; `LsCommand`, `CdCommand`, `ExitCommand` — реализации.
  Каждый метод `Execute` проверяет аргументы своей команды и возвращает `CommandResult`.
  Для новой команды создайте класс с интерфейсом `ICommand` и вызовите `RegisterCommand`.
  Менять диспетчер, парсер или цикл чтения для этого не нужно.
- `tests/ShellEmulator.Tests` — автономные проверки; `Main` запускает группы проверок.
  `CheckParser`, `CheckCommands`, `CheckRepl` проверяют соответствующие части программы.
  `Equal`, `ExpectParseError`, `Require` сравнивают результаты и регистрируют ошибки.
- `StageTwoTests.Run` — проверки параметров, ошибок сценария, реестра и запуска приложения.
  Методы `CheckOptions`, `CheckInvalidOptions`, `CheckScriptErrors`, `CheckRegistry`, `CheckApplication`
  проверяют соответствующие сценарии; вспомогательные методы проверяют успешный запуск и остановку.
- `run.bat`, `test.bat` — запуск приложения и тестов из корня репозитория.

## Git и требования к сдаче

Каждый этап сохраняется отдельным коммитом в формате Conventional/Scoped Commits.
Исходники и тесты разделены; сборочные файлы, бинарники и настройки редакторов исключены через `.gitignore`.
Для документации методов используется XMLDoc. Методы ограничены 40 строками, строки кода — 120 символами.

По условиям работы репозиторий при сдаче должен быть публично доступен.
Удалённый репозиторий: https://github.com/Povelitel-Blinow/Practica-Configa.
Публикация нового локального коммита:

```text
git push origin main
```
